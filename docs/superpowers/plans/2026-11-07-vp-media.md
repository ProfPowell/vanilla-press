# VP Media (step 3b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Media screen and editor media flow that work the way Ghost's do: upload anywhere, readable stable names, alt text with a decorative state, image edits as copies, audio/video/PDF as media types, a featured image, safe deletes, and a library that lives in git and follows the site.

**Architecture:**
- Pure, DOM-free modules hold the logic and are tested in Node:
  - `src/media/` (types, file inspection, names, limits, usage, the library view model). `src/` is served at `/src/` by both servers, so the app, the editor and the server import the same browser-safe modules.
  - `editor/assets/js/media-upload.js`, `media-insert.js`, `media-drop.js`, `alt-check.js` for the editor side.
- The store gains columns (media: `original_name`, `width`, `height`, `edited_from`; documents: `image`) through a small column migration. `content/media.json` is loaded and reconciled with `src/media` whenever the site is read from disk.
- The media API grows list-with-usage, checked upload, alt edit and guarded delete. The app server queues media writes, schedules draft backups for them, and serves media sandboxed with byte ranges.
- The app renders the Media screen (`app/assets/js/media-page.js`). The editor gets a rebuilt `<media-picker>`, palette entries, drop/paste, Choose… in component settings, the alt warning and Featured image.

**Tech Stack:** Node ≥22, `node:test`, better-sqlite3, ProseMirror (esm.sh in the browser; devDependencies in tests), Vanilla Breeze tokens and elements (`audio-player`, `video-player`), `@profpowell/image-editor`, `@profpowell/pdf-viewer`. Browser checks: the global Playwright at `/opt/homebrew/lib/node_modules/playwright`, axe from `/Users/tpowell/src/vanilla-breeze/node_modules/axe-core/axe.min.js`.

**Spec:** `docs/superpowers/specs/2026-11-03-vp-media-design.md`. Visual spec: `docs/design/mockups/Media.dc.html` and `docs/design/README.md` (read "How to read the mockups" and the token table first). Deferred items touching media: `docs/superpowers/followups/2026-11-07-vp-new-look.md` (media-picker `alert()`s; the title's `handleDrop` swallowing file drops).

## Plan rulings (made while planning, for the user to check)

- **M1, usage includes links.** "Used in" and the delete guard also count `link` hrefs to `/media/<file>`. A PDF inserted without the viewer is a link (goal 6), so the spec's list (figure, embed, component, `meta.image`) would let a published post's PDF be deleted. *Cost if wrong:* a file linked from a published post can't be deleted until the link goes.
- **M2, legacy empty alt.** Before 3b, every upload without alt text stored `alt: ''`. Loading a media.json entry with **no `original_name` key** turns `alt: ''` into `null`. The store migration does the same once, when it adds the columns. Otherwise every old upload would count as decorative and dodge the alt warning. *Cost if wrong:* an old image someone did mean as decorative shows "No alt text" until it's ticked again.
- **M3, `documents.image` column.** The store keeps meta in columns, so `meta.image` needs its own column and migration, or it's lost on the next load. The spec only names the media migration. *Cost if wrong:* none.
- **M4, byte ranges.** Media responses support single `Range` requests (206/416). Safari won't play or seek video without them. *Cost if wrong:* about 30 lines in `static.js`.
- **M5, media.json and adoption.**
  - If `content/media.json` is absent, the store's rows are kept. If it's present, it replaces them (the site wins).
  - Adopting stray files rewrites media.json and schedules a draft backup. Otherwise a dirty media.json would block pull-on-open (it refuses uncommitted changes in `BACKUP_PATHS`).
  - *Cost if wrong:* opening a site with strays makes one `Draft: media library [CI Skip]` commit.
- **M6, sizes.** The hard limit is 25 MiB (26,214,400 bytes), shown as "25 MB". The note threshold is 5 MiB (5,242,880 bytes). Sizes are shown in base-1024 units labelled KB/MB. *Cost if wrong:* a file between 25,000,000 and 26,214,400 bytes is accepted. Cloudflare's limit is 25 MiB, so it still serves.
- **M7, edited copies.**
  - The server takes `alt`, `original_name` and `edited_from` from the source row, not from the request.
  - Editing an edited copy doesn't stack suffixes: `garden-path-edited-a1b2c3.jpg` → `garden-path-edited-d4e5f6.jpg`.
  - *Cost if wrong:* none.
- **M8, featured image on the site.**
  - Cook layouts have no conditionals and leave `${image}` in the page literally when a post has none.
  - So the thomasapowell.com change adds a site-local Cook `default` plugin (`plugins/featured-image.js`). It sets the `featuredImage` and `ogImage` front-matter values to markup when `image` is set and to `''` otherwise. The layout uses `${featuredImage}` and `${ogImage}`.
  - The layout's featured `<img>` has `alt=""`: the title follows it, and front matter carries no alt.
  - *Cost if wrong:* a 20-line plugin in the site repo instead of a Cook feature.
- **M9, palette inserts after picking.** Image, Audio and Video open the picker first and insert only on a choice. Cancel inserts nothing. Today, Image inserts an empty figure first. *Cost if wrong:* none.
- **M10, backup messages.** Media changes call `backup.noteSaved({ title: <filename>, status: 'draft' })`, so the commit reads `Draft: garden-path-3f9a2c.jpg [CI Skip]`. Adoption uses the title `media library`. *Cost if wrong:* commit wording only.
- **M11, fixture mode adopts.** `vp serve` without a site adopts the files in the repo's `media/` into its store at start, so the picker shows them. It writes no media.json. *Cost if wrong:* fixture-mode store rows the user didn't upload.
- **M12, missing files can't be chosen** in the picker. They show "Missing file" and are disabled. *Cost if wrong:* none.
- **M13, missing files block Publish.**
  - Publish and Update refuse (422) a post that references a `/media/` file missing from `src/media`: `This post uses files missing from src/media: x.jpg. Remove them or add the files, then publish.`
  - This serves the anti-goal "a published post showing a broken file".
  - *Cost if wrong:* a post with a missing file can't go live until it's fixed.
- **M14, stored extension.** The stored extension is the original's, lowercased, when it belongs to the sniffed type (`photo.JPEG` → `.jpeg`). Otherwise it's the type's canonical one (a PNG named `.jpg` → `.png`). *Cost if wrong:* none.
- **M15, the alt warning runs in `vp serve` too** (its header Publish). *Cost if wrong:* none.

### Task 1: Media types, file inspection, names and limits

**Files:**
- Create: `src/media/types.js`, `src/media/inspect.js`, `src/media/names.js`, `src/media/limits.js`. All are browser-safe: they use `Uint8Array` and import no `node:` modules, except `names.js`, which uses `crypto.getRandomValues`.
- Test: `test/media/types.test.js`, `test/media/inspect.test.js`, `test/media/names.test.js`, `test/media/limits.test.js`

**Interfaces:**
- Produces:
  - `types.js`:
    - `ACCEPTED: Array<{ mime, kind: 'image'|'video'|'audio'|'pdf', label, exts: string[] }>`. The first ext is the canonical one:
      - `image/jpeg` JPEG image `[jpg,jpeg]`; `image/png` PNG image `[png]`; `image/webp` WebP image `[webp]`; `image/avif` AVIF image `[avif]`; `image/gif` GIF image `[gif]`; `image/svg+xml` SVG image `[svg]`;
      - `video/mp4` MP4 video `[mp4,m4v]`; `video/webm` WebM video `[webm]`;
      - `audio/mpeg` MP3 audio `[mp3]`; `audio/mp4` M4A audio `[m4a]`; `audio/aac` AAC audio `[aac]`; `audio/ogg` Ogg audio `[ogg,oga,opus]`; `audio/wav` WAV audio `[wav]`;
      - `application/pdf` PDF document `[pdf]`.
    - `typeOf(mime) => entry|null`, `kindOf(mime) => kind|null`, `typeLabel(mime) => string` (`'File'` when unknown).
    - `EDITABLE = ['image/jpeg','image/png','image/webp']`, `canEditImage(mime) => boolean`, and `exportFormat(mime) => 'jpeg'|'png'|'webp'|null`.
  - `inspect.js`:
    - `sniffType(bytes: Uint8Array, filename = '') => entry|null`. The magic bytes are:
      - `FF D8 FF` → JPEG; PNG signature; `GIF87a`/`GIF89a`; `RIFF….WEBP`; `RIFF….WAVE`; `%PDF-`; `OggS`; EBML `1A 45 DF A3` → WebM;
      - `ID3`, or an MPEG frame sync with layer ≠ 00 → MP3; ADTS `FFF1`/`FFF9` → AAC;
      - ISO `ftyp`: brand `avif`/`avis` (major or compatible) → AVIF; `M4A `/`M4B ` → M4A; other brands → MP4, except M4A when the extension is `m4a` or `aac` (generic `isom`);
      - SVG: the first 4 KB decode as text and, after an optional BOM, XML declaration, comments and doctype, the first element is `<svg`.
    - `imageSize(bytes, mime) => { width, height }|null`. It reads PNG IHDR, the GIF screen, JPEG SOFn, WebP VP8/VP8L/VP8X, AVIF `ispe`, and SVG `width`/`height` (unitless or `px`), else the `viewBox` width and height. Unknown or malformed gives null, never a throw.
    - `inspectFile(bytes, filename) => { mime, kind, ext, width: number|null, height: number|null }|null`. Here `ext` is `storedExt(filename, entry)`.
  - `names.js`:
    - `slugBase(name) => string`:
      - drop the extension; NFKD; strip combining marks; lowercase;
      - runs of `[^a-z0-9]` become `-`; trim `-`;
      - cut to 60 characters with no trailing `-`; `''` becomes `'file'`.
    - `shortId() => string`: 6 lowercase hex characters.
    - `storedExt(name, entry) => string` (M14).
    - `mediaFilename(originalName, ext, id) => `${slugBase(originalName)}-${id}.${ext}``.
    - `editedFilename(sourceFilename, ext, id) => string`. The base is the source without its extension, then without a trailing `-[0-9a-f]{6}`, then without a trailing `-edited`; the result is `${base}-edited-${id}.${ext}`.
    - `uniqueFilename(make: (id) => string, taken: (name) => boolean, tries = 20) => string`. It throws `Error('Could not find a free file name')` after `tries`.
  - `limits.js`:
    - `MAX_BYTES = 26_214_400`, `LARGE_BYTES = 5_242_880` (M6).
    - `formatBytes(n) => string`: `'512 bytes'`, `'812 KB'` (integer KB), `'4.2 MB'` (one decimal).
    - `ACCEPT_ATTR`: every ext in ACCEPTED as `.ext`, comma-joined.
    - `tooLargeMessage(name, size) => `${name} is ${formatBytes(size)}. Files over 25 MB can't be published (Cloudflare Pages won't serve them). Make it smaller and try again.``
    - `unsupportedMessage(name) => `${name} isn't a file type Vanilla Press accepts. Use JPEG, PNG, WebP, AVIF, GIF, SVG, MP4, WebM, MP3, M4A, AAC, Ogg, WAV or PDF.``
    - `LARGE_NOTE = 'Large file: everything is committed to git, so the repository grows by its size.'`
    - `checkBeforeUpload({ name, size }) => { ok: true, large: boolean } | { ok: false, error: string }`. It checks the size and that the extension is in ACCEPTED. The server's content check stays authoritative.
