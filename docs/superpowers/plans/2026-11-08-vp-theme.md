# Step 4: Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The look chosen in Vanilla Press (site theme, adjustments, custom themes, one post's own theme) is the look of the live site, set on a real Theme screen and in Post settings → Appearance.

**Architecture:** Three repos, in order. Vanilla Breeze's theme manager stops overwriting a theme the page sets (`data-theme-source="site"`, extra ids, authored `data-mode`, already-linked stylesheets). Cook gets a generic built-in `theme` plugin that reads `theme` from `config/main.js` or `config/theme.json` and writes `data-theme`/`data-mode`/theme `<link>`s per page, honoring front matter `theme`/`themeScope`. Vanilla Press writes `config/theme.json` and `src/assets/themes/*.css`, serves the site's own VB copy for previews, and adds the Theme screen, the Appearance section and the editor pane theme; Apply goes through the publish path.

**Tech Stack:** Vanilla JS ES modules, `node:test` in all three repos, linkedom (Cook tests), better-sqlite3 (VP), Playwright for Node browser checks (from `/opt/homebrew/lib/node_modules`).

**Spec:** `docs/superpowers/specs/2026-11-08-vp-theme-design.md` (with `docs/design/README.md` Theme and Page theme override sections, `docs/design/mockups/Theme.dc.html`, `docs/design/mockups/EditorTheme.dc.html`).

## Rulings (spec gaps this plan settles)

- **R1** `vp.json` `{ "theme": "default" }` (VP wrote it on every sync even with no choice) is not migrated: the key is dropped, no `theme.json` is written.
- **R2** On-disk `config/theme.json` and `src/assets/themes/vp-site.css` are the applied state: only Apply (and migration) write `name`, `mode`, `adjust`, `adjustments`. Unapplied choices live in the page until reload. Custom-theme library operations (save new, import, rename, delete) write at once (a library change, not a look change) and go live with the next Apply or Publish/Update.
- **R3** Publish/Update also commit `config/theme.json` and `src/assets/themes` (`THEME_PATHS`), so a migrated setting or a custom theme a post uses goes live with it. `THEME_PATHS` is not in `BACKUP_PATHS` (a backup push must not change the look).
- **R4** A site with no `theme.json` gets one (`name: "default"`, `mode: "auto"`) when a custom theme is created or a post with its own theme is published: using the Theme screen or a page theme is opting in.
- **R5** The site's VB copy is gitignored on thomasapowell.com (copied by `npm run vendor` before builds). When `files` must be written and no `vanilla-breeze.css` is found under `src/`, VP runs `ensureInstalled` + `runBuild` once and looks again; still none and a non-built-in VB theme is needed → 422 "This site has no copy of Vanilla Breeze under src/, so only themes built into Vanilla Breeze can be applied."
- **R6** Cook needs to know which themes have one scheme; it reads the generic `modes` map (VP derives it from `custom[].only`). Forced scheme precedence: `modes[id]` > site `mode` (light/dark) > none.
- **R7** Adjustments file `vp-site.css` is unlayered (beats every layered theme rule whatever its specificity), scoped to `[data-theme~="vp-site"]` with dark variants. Hue reaches every theme because VP writes literal `--color-primary` and `--color-interactive` per scheme, computed in the browser from the base theme with `oklch(from var(<token>) l max(c, 0.1) <hue>)` (min chroma 0.1 so achromatic primaries visibly change), plus `--hue-primary`.
- **R8** Font choices are VB's three stacks (`--font-sans`, `--font-serif`, `--font-mono` values from VB `src/tokens/typography.css`), written as literal stacks to `--font-heading` / `--font-body`. Corners: Square sets `--radius-xs, -s, -sm, -m, -l, -xl, -2xl` to `0`; Round sets them to `0.375rem, 0.5rem, 0.625rem, 0.75rem, 1rem, 1.25rem, 1.5rem`.
- **R9** "Reset" clears hue, fonts, corners and sets the scheme to Reader's choice.
- **R10** A saved theme ("Save as a new theme…") holds the computed values of the custom properties the base theme's CSS declares plus the adjusted tokens, in both schemes. Decorative non-token rules of showcase themes (8bit's pixel borders, etc.) are not carried over (the spec says tokens).
- **R11** A Composer import with one block is "Light only" unless its `--color-background` is dark (OKLCH L < 0.5, or hex/rgb luminance < 0.5), then "Dark only". A dark block (`@media (prefers-color-scheme: dark)` or `[data-mode=dark]`) makes it both. Declarations whose value contains `url(`, `{`, `}`, `<`, `;` or `@` are dropped and listed, as is every non-custom-property rule.
- **R12** Renaming keeps the id (posts and `theme.json` refer to it).
- **R13** Article scope with `mode: auto`: Cook only writes `data-mode` on the article when forced (R6); otherwise the article shows its theme's default scheme. Documented in Cook's docs.
- **R14** "All N themes" expands the grid in place (spec), not the mockup's external library link. The first 8 cards: the current theme, then custom themes, then the list order.
- **R15** Apply's "Live ↗" uses a live check of the site's home page: `<html data-theme>` equals the applied ids.
- **R16** VP's `vanilla-breeze` dependency is `file:../vanilla-breeze`, so there is nothing to bump in VP. thomasapowell.com's ranges become `vanilla-breeze ^0.6.0` and `cook-ssg ^2.6.0`, assuming the user releases VB 0.6.0 and Cook 2.6.0.
- **R17** Page front matter themes apply to HTML pages with front matter (`file.frontMatter`); Markdown pages are not themed per page (documented).

## Review Focus

1. **A site that never opted in** (no `theme.json`; or `vp.json` with `theme: "default"`): Cook output has no `data-theme-source`, no theme link; VP writes nothing. Tests: Task 4 "no setting: output unchanged", Task 8 "migration skips default".
2. **Hand-edited or hostile front matter** (`theme: "Retro!"`, `theme: "x\" onload=\"..."`, `themeScope: "sidebar"`): ignored with one `[theme]` warning naming the page; the page keeps the site theme / default scope. Tests: Task 3 and Task 4.
3. **A returning visitor with a stored brand** on a page with `data-theme-source="site"`, on one without it, and with `a11y-*` ids: site brand wins only with the source attribute; extra ids and a11y ids always survive. Tests: Task 1.
4. **An odd Composer file** (`:root, html {}` lists, a dark `@media` block, `@import`, `@font-face`, `body {}` rules, `url(...)` values, a `}` inside a comment, 300 KB): scoped output, dropped list, 413 over the limit. Tests: Task 6.
5. **Apply on a fresh clone** with no vendored VB (the clone of thomasapowell.com has none until a build): one build to vendor, then files are written; 422 with the R5 text when still none. Tests: Task 9.
